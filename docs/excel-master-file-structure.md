## לוגיקת ייבוא

### 1. זיהוי שורות "Header של קבוצה"
בגליונות `הוצאות חומרים` / `הוצאות קבלנים` / `תקורות`, **שורות שיש להן רק טקסט בעמודה A (השם של הספק/קבלן/קטגוריה) ושאר העמודות ריקות** = header row של קבוצה.

**דוגמה (תבנית)**:
```
שורה 4:  "[שם ספק כלשהו]"   ריק   ריק   ריק   ריק   ריק   ריק   ← header
שורה 5:  2024-12-18  [שם הספק]  פירוט  1589.74  0  1589.74  SI...  ← נתון
שורה 6:  2024-12-26  [שם הספק]  פירוט   334.19  0   334.19  SI...  ← נתון
...
שורה 11: ריק  "סה"כ [שם ספק]"  ריק   1115352  0  1115352  ריק   ← total row (skip)
```

ה-importer:
- מזהה את שם הספק/קבלן/קטגוריה מהשורה ה-header.
- יוצר רשומה ב-`suppliers/` או `contractors/` אם עוד לא קיים.
- כל שורת נתון אחריה — `expenses/` עם `supplierId` או `contractorId` מהקבוצה.
- שורת "סה"כ" — **מדלגים** (לא מייבאים, האפליקציה מחשבת לבד).

### 2. תקורות — תת-קטגוריה בתוך הקטגוריה
בגליון `תקורות`, ה-header rows מקבצות לפי קטגוריה (לדוגמה: `שכ"ע – עלות המכר (מיון לפי עובד)`).
בתוך הקטגוריה, עמודה B מכילה תת-קטגוריה (לדוגמה `[עובד 1511] שכ"ע ריכוז`).

**הצעת מיפוי**:
- `category` = "תקורות"
- `subCategory` = הטקסט מ-header (לדוגמה "שכ"ע - עלות המכר")
- `payeeOrSource` = הטקסט מעמודה B של השורה (לדוגמה "[עובד 1511] שכ"ע ריכוז")

(נדרשת תוספת קטנה לסכמת `expenses/` — שדה `subCategory` אופציונלי.)

### 3. סימני סכומים
- **חובה (₪)** = הוצאה (חיוב) — נכנס ל-`amount` חיובי.
- **זכות (₪)** = החזר / זיכוי — אם > 0, ה-`amount` יהיה שלילי.
- **נטו (₪)** = חישוב = חובה - זכות. שורות עם `נטו` שלילי = `CV...` (Credit Voucher / זיכוי).

### 4. מספר אסמכתא — הקידומת מציינת סוג
- `SI...` = Sales Invoice (חשבונית קנייה) — הוצאה רגילה
- `CV...` = Credit Voucher — זיכוי, שלילי
- `IV...` = Invoice (חשבונית הכנסה) — לזהות אם זה ב-`income/`
- `PO...` = Purchase Order — הזמנת רכש (Phase 8, יקושר ל-`purchase_orders/`)

### 5. תאריכים
אקסל שומר אותם כ-datetime objects. JavaScript Date conversion ישיר.

### 6. סכומים שליליים (זיכויים)
חייבים להישמר, חשובים לסיכומים נכונים.

### 7. שדות סטטוס בגליונות שירות
`✓ רשום בהנה"ח` = החשבון אושר ונרשם בהנהלת חשבונות (= `status: 'approved'` ב-`boq_revisions/`).

## הקשר לסכמת PM ATUAN (PLAN.md סעיף 6)

### `boq_revisions/{revisionId}` — מהגליון "גיליונות שירות"
מיפוי שורה → רשומה:
```
revisionNumber       = "גיליון מס׳" (1, 2, 3...)
billDate             = "תאריך חשבונית"
totalAmount          = "סה"כ כולל מע"מ"
status               = derived מ"סטטוס" ("✓ רשום בהנה"ח" → 'approved')
notes                = "הערות"
```

### `income/{incomeId}` — נוסף מהגליון "גיליונות שירות"
```
invoiceNumber        = "מספר חשבונית (IV)"
date                 = "תאריך חשבונית"
amount               = "סכום לפני מע"מ"
vat                  = "מע"מ ₪"
clientId             = ref ל-clients/ (הקבלן הראשי, במקרה הזה י.ר.ן)
linkedBoqRevisionId  = ref ל-boq_revisions/ של אותה שורה
currency             = 'ILS' (קבוע במקרה הזה)
```

### `expenses/{expenseId}` — מ-3 הגליונות
```
date                 = "תאריך"
description          = "פרטים"
amount               = "נטו" (יכול להיות שלילי לזיכויים)
invoiceNumber        = "אסמכתא"
category             = "חומרים" / "קבלן משנה" / "תקורות" (לפי הגליון)
subCategory          = (רק לתקורות) header row של הקבוצה
supplierId / contractorId = ref מ-header row
projectId            = הפרויקט אליו שייך הקובץ
```

### `suppliers/{supplierId}` ו-`contractors/{contractorId}`
נוצרים אוטומטית מ-header rows בגליונות חומרים / קבלנים.
שדה `name` = הטקסט מה-header. שדות אחרים נשארים ריקים בייבוא ראשוני; המשתמש ימלא בהמשך.

## תיקונים נדרשים בסכמת PLAN.md (לעדכון בגרסה הבאה)

1. **שדה `subCategory` ב-`expenses/`** — אופציונלי, מאפשר תת-קיבוץ של תקורות.
2. **תמיכה ב-`amount` שלילי** ב-`expenses/` — לזיכויים (CV).
3. **שדה `linkedBoqRevisionId` ב-`income/`** — כבר קיים בסכמה 3.4 ✅.
4. **הסטטוסים של חשבון חלקי**: `'draft' | 'submitted' | 'approved' | 'paid' | 'rejected'` — תואם למה שראיתי בקובץ ✅.
